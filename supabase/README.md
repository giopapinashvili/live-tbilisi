# ბაზა — თბილისი LIVE

პროექტი: **tbilisi-live** · რეგიონი: **eu-central-1 (Frankfurt)** · გეგმა: **Free ($0/თვე)**

ფრანკფურტი განზრახ: თბილისიდან ~3000 კმ-ია, ტოკიო კი ~8000.
ფიდში ათეულობით მოთხოვნაა და ეს სხვაობა შესამჩნევია.

---

## რა სად ცხოვრობს

ორი მონაცემის სიბრტყე გვაქვს და ეს პროექტის ხერხემალია:

| | სად | რატომ |
|---|---|---|
| **ბიზნესები** (30 000) | სტატიკური ბანდლი, CDN | წაკითხვა უფასოა. ბაზიდან იგივე ფული ღირდა |
| **ხალხი და მათი ქმედება** | Postgres | იცვლება, პირადია, დაცვა სჭირდება |

ბიზნესი ბაზაში **არ დუბლირდება**. კავშირი `business_slug`-ით ხდება —
ტექსტით, არა უცხო გასაღებით. ასე ბანდლის ხელახლა აგება ბაზას არ ამტვრევს.

## რატომ არის დაცვა ბაზაში და არა კოდში

ბრაუზერში გაშვებული JavaScript ყოველთვის შეიძლება შეიცვალოს.
თუ „სხვისი პოსტი ვერ წაიშლება" მხოლოდ კოდში წერია, ეს დაცვა არაა.

ამიტომ ყველა ცხრილს **RLS** უდგას: ვინ რას ხედავს და ვინ რას ცვლის,
Postgres-ში წერია. კოდი რომ სრულად გატყდეს, მონაცემი მაინც დაცული რჩება.

მაგალითი — კომენტარის წაშლა:

```sql
create policy "comments_delete" on comments for delete using (
  auth.uid() = author_id
  or exists (select 1 from posts p where p.id = post_id and p.author_id = auth.uid())
);
```

წაშლა შეუძლია ან კომენტარის ავტორს, ან იმ პოსტის პატრონს —
ზუსტად როგორც ინსტაგრამზე. სხვას ბაზა უბრალოდ არ დაანებებს.

---

## შიდა ფუნქციები

Supabase ყველა ფუნქციას, რაც `public` სქემაშია, ავტომატურად
გამოაქვს `/rest/v1/rpc/...` მისამართზე. ანუ ინტერნეტიდან იძახება.

ჩვენი ტრიგერები და დამხმარეები `private` სქემაშია — იქიდან
API-ს არაფერი გამოაქვს, ტრიგერები კი ისევე მუშაობს.

---

## სატესტო მონაცემი

`profiles`, `posts`, `promos` და `business_items` ცხრილებს აქვს `is_demo`.
სატესტო და ნამდვილი არასდროს ერევა.

გასუფთავება:

```sql
select * from private.wipe_demo();
```

`cascade` თვითონ წაიღებს პოსტებს, კომენტარებს, მოწონებებს და
გამოწერებს. ნამდვილ ანგარიშს არ ეხება.

ფიდის სატესტო პოსტები ცალკე დგას — ისინი სტატიკურ ბანდლშია:

```
npm run test-data:clean
```

| თარო | ჭერი | რა |
|---|---|---|
| `avatars` | 5 მბ | პროფილის სურათი, 400 პიქსელამდე იჭრება |

ატვირთვამდე ფოტო ბრაუზერშივე მცირდება და WebP-ად იქცევა:
6 მბ → ~250 კბ. ეს მოხერხებულობა არაა — უფასო გეგმის საცავი
სხვაგვარად კვირაში ამოიწურებოდა.

გზა ყოველთვის `<uid>/<ფაილი>`. წესი მხოლოდ საკუთარ საქაღალდეში
წერას უშვებს, ამიტომ სხვისი ფოტოს გადაწერა შეუძლებელია.
